## Experimental client/server/storage migration

ICE `packages/protocol/src/schemas.ts` still declares protocol version **1** and validates business commands/session snapshots. Pi `packages/protocol/src/protocol.ts` declares version **8**: opaque service calls, `{serverId, sessionId, attachmentId}` route fencing, cancellation, subscription updates, and attachment changes. Chord owns the service grammar and replicated-state semantics. This must be a coordinated client/server/protocol/application migration, not a version-constant edit.

Required packages/files: `packages/protocol/src/{codec,framing,index,protocol}.ts`; `packages/client/src/{client,errors,index,transport,types,unix}.ts`; `packages/server/src/{connection,errors,index,listener,server,session-router,types}.ts` plus `testing/*` and `transports/unix/*`. Full changed/deleted path inventory is retained separately.

Client changes: generic `Client` and `createClientServiceTransport`, lazy typed service bindings, snapshot hydration followed by start, attachment invalidation, explicit reconnect with no automatic request replay, bounded Unix discovery. Server changes: routed application-owned service host/session handle; multiple presentation attachments; delayed frame fencing; settlement before attachment release; worker shutdown ownership; private generation/demand lifecycle. Transport peer authentication remains host policy.

Pi [ae2cc511](https://github.com/earendil-works/pi/commit/ae2cc511), [1a7bc80e](https://github.com/earendil-works/pi/commit/1a7bc80e), [fa503683](https://github.com/earendil-works/pi/commit/fa503683), [48dd1e2f](https://github.com/earendil-works/pi/commit/48dd1e2f).

Pi also deletes ICE's still-present `packages/agent/src/harness/*`, `packages/agent/src/node.ts`, and `packages/storage/sqlite-node/*`. It removes `AgentHarness`, old sessions/storage/tools/compaction/skills/prompts/search exports from agent-core and points durable consumers at pi-durable. Existing ICE SQLite code imports those exports, so deleting them first breaks consumers. This is an upstream breaking migration; source removal still requires user approval under this worktree's rules. Preserve old data and define a tested migration or explicit coexistence boundary before retiring it. No automatic removal is proposed here.

## Integration order and completion criteria

First isolate P0 safety/correctness fixes (R1–R4, compaction/persistence/provider fixes in other reports). Then migrate AI transcript/provider contract + stable agent R6–R9 + coding-agent context/session/extension consumers coherently. Next adopt providers/model capabilities/auth and TUI/RPC logic with ICE overlays preserved. Add MCP/codemode feature parity behind ICE approval/trust gates. Decide Chord/durable/client-server migration separately; full experimental parity cannot honestly be claimed while it remains deferred.

For each implementation slice: record clean baseline in an isolated writer worktree; port relevant upstream tests, use faux providers; run affected focused tests from package roots; then `corepack npm@12.0.2 run check` with complete output. Changes to ICE children, mode policy, protected paths, graceful-stop hooks, view bridge, cache affinity, catalog composition, compaction settings, or Curax transport need the corresponding existing ICE regression checks. No check result in this audit should be interpreted as a pass: checks were not run and no source was changed.
